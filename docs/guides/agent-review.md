# PR-Agent diff review

Comment exactly `/agent-review` on an open pull request from the same repository. Only the designated maintainer's original comment qualifies. Edited comments, arguments, workflow reruns, other accounts, bots, plain issues, closed PRs, and fork PRs cannot admit provider work. The workflow must already be on the default branch; a comment on the PR installing it doesn't exercise the proposed version. See GitHub's [issue-comment event contract](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#issue_comment).

Findings appear on changed lines as resolvable review threads, with a persistent summary for findings that can't be anchored safely. A separate completion record names the captured base/head, reviewer source, caller profile revision and hash, actual models, reported token usage, and declared exclusions. Repeated commands for the identical completed snapshot link to that record without another inference. Running, failed, partial, stale, or unverified records never qualify for reuse. The bot-owned summary must still match the ID and content hash in its completion record; deleted, edited, or replaced summaries require another review. A changed base/head, profile content, reviewer source, or central model configuration requires another review.

This optional command runs alongside [`/review`](pr-review.md) and CodeRabbit. It reviews a bounded static diff with nearby context. It can't explore or execute the repository, commit repairs, approve a PR, or change labels. There is no `/agent-review deep` or `/improve` mode. Findings are advice and can be wrong; successful execution alone doesn't establish review quality or recall.

## Shared source and repository policy

[The caller](../../.github/workflows/agent-review.yaml) delegates to [the reusable workflow](../../.github/workflows/agent-review-reusable.yaml). Pipelock uses a local reference so its own caller loads the same immutable revision. Other repositories must use `pipelab-org/pipelock/.github/workflows/agent-review-reusable.yaml` at a full 40-character merged commit SHA, followed by the `# main` tracking comment. Never use an executing branch or tag reference. GitHub documents [local and remote reusable references](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_iduses).

The credential-free [source helper](../../.github/workflows/pr-review-source.yaml) validates GitHub's loaded workflow identity. Its SHA selects the explicit `pipelab-org/pipelock` checkout at `trusted-agent-review`. Ordinary checkout inside a reusable workflow reads the caller, so it can't select the shared engine. The caller profile and caller workflow are checked out separately at the caller's captured `github.workflow_sha`, never the PR head. Checkout credentials are disabled. Only Python from the shared source executes; caller files remain bounded data. See GitHub's [caller context and checkout behavior](https://docs.github.com/en/actions/concepts/workflows-and-actions/reusing-workflow-configurations#reusable-workflows) and [job workflow identity](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#job-context).

[Common configuration](../../.github/pr-agent.toml) owns models, budgets, provider handling, restricted operation, output, telemetry, and the anti-injection rubric. [The repository profile](../../.github/agent-review.toml) permits exactly these fields:

```toml
[review]
instructions = "Review material correctness defects against this repository's contracts."

[ignore]
glob = ["**/vendor/**"]
```

The profile can't change credentials, publishing target, admission, callbacks, approval, retries, models, or budgets. Unknown fields, malformed TOML, non-regular files, symlinks in any path component, and files larger than 65,536 bytes are rejected before inference. Instructions append to the common rubric. Exclusions are explicit and disclosed separately from files omitted for budget reasons. Pipelock retains its existing generated protobuf, dependency, `testdata`, and selected lock-file exclusions; another repository must choose exclusions appropriate to its source and fixtures.

The shared [caller/profile validator](../../scripts/agent_review_contract.py) requires the exact maintained caller template, named secret mappings, identity gate, event, permission ceiling, and trusted source SHA. Its executable revision and expected pin must be selected by trusted default-branch code, never by the proposed caller's contents. It also requires GitHub's caller `github.workflow_ref` to name that same `.github/workflows/agent-review.yaml`, so another workflow file can't call the shared engine behind a matching decoy caller. The local caller form is accepted only in `pipelab-org/pipelock`. Profiles and workflows are read through the same bounded no-symlink reader used by the existing caller contract.

## Credentials and spending

Callers map only `ANTHROPIC_API_KEY`, `ANTHROPIC_API_KEY_2`, and `OPENAI_API_KEY` from repository or organization secrets. Each is individually optional; at least one configured provider is required for new inference. Don't use `secrets: inherit`, environment secrets, a PAT, or a custom GitHub-token secret. The caller repository's `github.token` handles GitHub operations. Hosting the engine in Pipelock doesn't supply Pipelock's secrets to another caller. See GitHub's [secret passing rules](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows#using-inputs-and-secrets-in-a-reusable-workflow).

The primary model remains `anthropic/claude-sonnet-5-5`, with `gpt-6-luna` as the configured OpenAI fallback. Only a reviewed central configuration change can select models. The second Anthropic key is used only after explicit billing rejection of the first. An absent first key skips both Anthropic slots, and an orphaned second key is ignored. Missing providers are skipped before inference.

Fallback requires a structured rejection with HTTP status 400, 402, or 429: Anthropic `error.type = "billing_error"`, Anthropic `error.type = "invalid_request_error"` with `credit balance is too low` in its message, or OpenAI `error.code = "insufficient_quota"`. Anthropic's [SDK billing schema](https://github.com/anthropics/anthropic-sdk-python/blob/v1.15.0/src/anthropic/types/shared/billing_error.py#L11) and [billing description](https://github.com/anthropics/anthropic-sdk-python/blob/v1.15.0/src/anthropic/types/beta/sessions/beta_managed_agents_billing_error.py#L23), plus [the pinned reviewer's legacy recognition](https://github.com/the-pr-agent/pr-agent/blob/8e5a9295973b24af4b70cafd0b660a230811ef9e/pr_agent/tools/pr_reviewer.py#L83), define those signals. Timeouts, dropped connections, ordinary rate limits, authentication errors, malformed output, and truncated completions fail without another paid attempt. Rejected slots remain retired for that run. Both completion-client and transport retries are disabled.

The inherited operator budgets remain three successful completion calls, a 90,000-token planning/context ceiling, 16,000 output tokens per call, a 300-second provider timeout, ten findings, and a 25-minute review job. These aren't claims about model capacity or monthly dollar limits. Oversized reviews list omitted files and fail as incomplete. Actual provider usage is reported when available, without prompts or credentials; provider account/project limits remain the spending backstop. Compare measured usage with current provider prices before changing a budget.

Authorized review jobs serialize by caller repository and PR, after admission, with `cancel-in-progress: false` and `queue: max`. This keeps a later command from silently replacing a pending one. Reuse avoids repeat inference for an already completed identical snapshot. GitHub concurrency remains repository-scoped, so a shared workflow doesn't create an organization-wide provider quota. See [concurrency behavior](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency).

## Failure visibility and permissions

Top-level permissions are empty. The caller job allows only `contents: read`, `issues: write`, and `pull-requests: write`, which are the ceiling for its children. Source binding has no token permissions; admission has `pull-requests: read` and no provider secrets. The container keeps the existing checkout and publication permissions. Provider secrets appear only on the inference step. Called workflows can't elevate their [caller's permission ceiling](https://docs.github.com/en/actions/reference/workflows-and-actions/reusing-workflow-configurations#access-and-permissions-for-nested-workflows).

The separate host-run notifier depends on source, admission, and review results. It uses only `pull-requests: write`, with no container, checkout, artifacts, provider secrets, or model. It repeats the original command/identity checks, validates the original repository and PR number, and re-reads same-repository/open-PR eligibility even when admission produced no outputs. It creates or updates a bot-owned status comment for that run using fixed text, captured commits when available, and an Actions link. Unauthorized commands, plain issues, closed PRs, and forks get no notification. Exception bodies, PR titles, branch names, model text, and logs aren't copied into comments. GitHub documents the [issue-comment endpoint's permission alternatives](https://docs.github.com/en/rest/issues/comments#create-an-issue-comment).

This covers failures scheduled through the dependency graph: checkout, profile validation, missing credentials, provider/output/coverage errors, changed commits, container startup, review timeout, and cancellation when GitHub schedules the notifier. Whole-workflow cancellation, invalid YAML, an unavailable reusable workflow, and runner/GitHub outages can prevent the notifier from running. A failed notification keeps Actions red. See GitHub's [needs results](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#needs-context) and [status functions](https://docs.github.com/en/actions/reference/workflows-and-actions/expressions#status-check-functions).

## Runtime and maintenance

The upstream image remains `pragent/pr-agent:0.47.0@sha256:7d98954c29289846a08faf00aaea0f1f1375b1676cd8a2ed303e0af07010af7a`. This is an inspected repository pin, not a claim about the latest upstream release. It runs as UID/GID 1001:1001 with all capabilities dropped and no new privileges. UID 1001 matches the [hosted Ubuntu runner](https://github.com/actions/runner-images/issues/10936), permitting workspace/file-command writes. GID 1001 excludes the runner's Docker group, so the mounted Docker socket remains unreachable. GitHub supplies a writable home at `/github/home`. Keep the hardening comments beside the options; a runner UID change needs checkout/cache-write proof, rather than restoring root or filesystem-bypass capabilities. See [container job options](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/run-jobs-in-a-container).

The adapter invokes only PR-Agent's reviewer. It disables remote/global/per-directory settings, skills, artifacts, related-ticket analysis, callbacks, telemetry, auto-approval, and label changes. PR metadata, fixture payloads, code comments, and earlier review text are untrusted data. The model has no tools, environment access, or authority over credentials or the publishing target. Captured commits are checked before publication and before marking success.

Keep Renovate as the existing updater. Its [GitHub Actions manager](https://docs.renovatebot.com/modules/manager/github-actions/) recognizes container digests and reusable references; the SHA remains the executing reference and `# main` supplies tracking metadata. Confirm dependency extraction with the installed Renovate version before relying on new caller updates. A central merge doesn't move pinned callers. Image, adapter, and central-configuration changes need unit tests, the actual pinned runtime tests, and a post-merge smoke test before callers adopt the new SHA.

Run the repository checks:

```bash
python3 -m unittest discover -s scripts -p '*test*.py'
python3 -m unittest scripts.test_pr_agent_review scripts.test_agent_review_contract
```

In a disposable environment with `pr-agent==0.47.0`, `python scripts/pr_agent_review.py --check-config` prints only allowlisted effective settings without model calls. Prepare tokenizer data without credentials before blocking networking:

```bash
python -c "import tiktoken; tiktoken.get_encoding('o200k_base')"
```

Keep that cache and set `TIKTOKEN_CACHE_DIR` to a writable location. Then run `python -m unittest scripts.test_pr_agent_runtime` with networking blocked. It exercises the actual pinned handler, parser, billing rollover, ambiguous-failure refusal, diff reads, publication, and successful-snapshot reuse with fixture credentials. A skipped runtime suite doesn't prove image compatibility.

For a new repository, copy the maintained caller shape, replace its local `uses` with the full merged shared-source SHA plus `# main`, map exactly the three named secrets, and add a repository profile. Add a secretless contract workflow using the central validator at a separately trusted pin. Its unprivileged PR job may test the proposed installation; its default-branch enforcement must execute trusted validator code and read head files only as data. Don't run proposed Python or dependency installers in a privileged `pull_request_target` job. The first installation can't enforce its own new trusted workflow before merge. Keep existing `/review` callers and their approved-pin contracts separate.

After merging the central extraction, resolve its actual merged SHA for installation pins. On a small same-repository PR with a known harmless defect on an added line, post a fresh exact command. Verify model acceptance, inline anchoring, resolvable threads, persistent summary, profile/source/commit identities, exclusions, usage, and run linkage. Repeat the command and confirm no additional inference. Exercise a controlled pre-inference failure and verify the host notifier's minimal token can comment. Offline fixtures cover billing rollover without draining real credits. Real model/account access, GitHub permissions, nested source/profile composition, default-branch triggering, queue behavior, and cross-repository use require live proof after merge.

Keep a review-quality record with exact snapshots and revisions, coverage, usage/runtime, finding links, and maintainer dispositions. Separate accepted repairs, already-covered findings, duplicates, evidence-backed rejections, unresolved findings, and later discovered misses. Review it during dependency maintenance and after material misses or provider changes. Tune one demonstrated problem at a time; repository context belongs in profiles, while safety/parser/provider fixes belong in the shared engine. Roll back by a reviewed caller/profile revert or by disabling the caller. No required check, release, or deployment is part of this optional command.
