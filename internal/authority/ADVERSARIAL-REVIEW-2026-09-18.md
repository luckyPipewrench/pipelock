# External action-authority verifier adversarial round

Review base: `6d497601b`. Scope: the external action-authority verifier in `internal/authority` and its forwarding integration. This is a report-only round before the lifetime and not-before change.

## Findings

1. **CONFIRMED-REPORT-ONLY: grants have no maximum lifetime or not-before value.** `validateGrant` accepts any parseable `expires_at`, and `Verify` only rejects it when the clock is at or after that timestamp. A disposable test with a signed `9999-12-31T23:59:59Z` grant was prepared, but the workstation admission guard refused `go test` before Go started: `t3-heavy-tool: shared admission storage is unavailable at /home/josh/.cache/t3-heavy-admission; refusing unbudgeted work`. The static path is `local.go:251-262` followed by `local.go:130-132`.
2. **CONFIRMED-REPORT-ONLY: shipped commands cannot install this verifier.** At the base, `git grep -n 'WithAuthorityVerifier' 6d497601b '*.go'` returns the option definition and proxy tests only. Every production `proxy.New` call, including `pipelock run` in `internal/cli/runtime/server.go:712`, omits it. Searches of `internal/config`, `internal/cli`, `cmd`, `configs`, and command documentation found no external-action-authority field or flag.
3. **CONFIRMED-REPORT-ONLY: operators have no documentation for this feature.** `rg -n -i 'action.authority|action-authority|external authorization|external action' docs README.md` returned no match.
4. **CONFIRMED-REPORT-ONLY: the PR #1575 JCS/NFC repair is present.** `local_test.go:289-339` contains the named canonicalization fixture with raw `&` and `<active>` in its destination. The target test could not run for the same admission refusal above, so this round confirms the committed regression fixture and implementation path but does not claim a fresh execution.

## Ten-point round

1. **STATES.** The configured state is unit-tested across fetch, forward HTTP, CONNECT, WebSocket, and MCP stdio/HTTP/WebSocket through `internal/proxy/authority_test.go`. The production state is unconfigured because no command builds a verifier, and `authority.Evaluate` treats `nil` as a bypass. There is no authority reload state, persisted verifier state, mixed-version protocol, or post-successful-run state. The base contains PR #1575 `931520b0`; its JCS/NFC fixture remains in the reviewed tree. A future merge must inspect that `not_before` is included in the signed-field allowlist and both canonicalization helpers, not only that it compiles.
2. **DIRECTION.** Once installed, `authority.Evaluate` denies malformed carriers, missing references, deny, indeterminate, verifier errors, and timeouts. The proxy transport tests demonstrate denied actions do not forward or dial. With no verifier installed, missing and invalid authority material do not block the action, which is the deliberate compatibility bypass rather than a successful authority result. There is no authority-specific CLI conclusion, dashboard badge, receipt field, or public API result. The existing machine-readable result is carried only into internal refusal handling.
3. **BLAST RADIUS.** The local verifier is consumed by the proxy forwarding gates and the carrier code. No TypeScript, Python, or Rust verifier implements this compact local grant format, and no capability manifest, dashboard, playground, or SDK advertises it. The signed-field lists are duplicated in `localGrant`, `validateNFCGrantStrings`, and `signTestNamedCanonGrant`; no parity test currently proves they agree. The implementation change must update all three and add a direct named-canon test.
4. **SHOULD THIS EXIST, THEN SHAPE.** A lifetime limit bounds replay after a signed exact-action grant leaks. A not-before value rejects grants that a trusted issuer signed for later use. The grant's signed payload changes, but the requested change does not alter receipts, AARP, or the five offline receipt verifier implementations. The closest published authority is the IETF OAuth Transaction Tokens BCP: transaction tokens "SHOULD have a time-to-live of less than 5 minutes." Its transaction token is the closest published analogue because it authorizes a single external action with bounded scope. This round adopts a five-minute maximum as the product default, subject to the code treating a grant at exactly five minutes as valid. The IETF document also says operators should work backward from endpoint latency SLOs, so a future operator surface must be an explicit product decision. Source: <https://datatracker.ietf.org/doc/draft-oauth-transactiontokens-bcp/> section 3.3. The alternative, leaving issuer time unconstrained because the verifier is not yet wired, preserves a long replay window in every future installation. The shape is a required signed `not_before`, paired with `expires_at`, so the verifier can calculate lifetime without trusting an unsigned local issue time.
5. **CLASS, NOT INSTANCE.** The temporal-window search found parallel time validation in AARP SVID bundle generations, TLS certificates, containment service expiry, and metrics exposure. Those use different artifacts and consumers. The only compact external action-grant implementation is `internal/authority/local.go`; no sibling local authority verifier exists. The grant change must cover legacy and named-canon payloads, issuer, action, and destination mismatch paths, expired and future-not-before boundaries, and every carrier through the shared verifier.
6. **VACUITY.** No new guard exists in this report-only phase. Phase two will neutralize only the new lifetime comparison in a temporary worktree edit, register an EXIT trap before execution, and run the over-lifetime case under a shell deadline. That case must fail with the guard present and allow with it neutralized. The permanent table will also prove an unmodified valid fixture allows, so an unconditional deny cannot pass the suite.
7. **PREDECESSOR AUDIT.** PR #1575 added named canonicalization, exact signed-field validation, and legacy handling. This round inspected its raw-ampersand fixture and the implementation path that parses with JCS, checks NFC, and signs the original canonical bytes. No new canonicalization defect is reported. The phase-two predecessor risk is field drift: adding `not_before` to only one of the three signed-field lists would reject valid named-canon grants or permit an unchecked field.
8. **EVIDENCE ORIGIN.** The verifier trusts a signed external grant only after a pinned local issuer key verifies it. Tests create their own signature, so they prove Pipelock's parser and verifier agreement, not a third-party issuer integration. The JCS fixture is a real raw JSON producer shape rather than Go's serializer output. The lifetime default comes from the IETF transaction-token publication, not a guessed duration. The fresh Go execution evidence is unavailable because the admission guard refused the test before execution.
9. **AVAILABILITY AND OPERABILITY.** The feature is inert in every shipped `pipelock run` path. An operator cannot supply a trusted issuer, revocation source, clock policy, or verifier option through configuration or a flag. A lifetime bound will therefore harden an unshipped Go API, not an operator-usable control. Configuration and CLI wiring are out of scope for this change and require Josh's approval because they add a public operator contract. Documentation is also out of scope because it would describe a control nobody can enable.
10. **HONEST CONVERGENCE.** This round is not dry. The maximum-lifetime and not-before defects are confirmed, and the verifier's lack of an operator installation path is a separate confirmed product gap. Phase two may fix only the signed-grant temporal window. It must not present the verifier as a shipped enforcement control.

## Decisions for Josh

- **Receipt binding:** keep out of scope. Binding a verified grant into signed receipts changes the receipt format and five verifier implementations.
- **Operator configuration and CLI:** keep out of scope. The verifier needs an explicit configuration, key-distribution, revocation, reload, and diagnostics design before an operator can enable it.
- **Documentation:** keep out of scope. Documentation should follow an enablement decision rather than describe an inert feature.
- **Redirect re-verification and replay:** keep out of scope. Both require a transport and state design beyond signed-grant validity.
